# Игровой аддон Chronicles Donation Bridge

Аддон принимает только команды из локального named pipe
`\\.\pipe\ChroniclesDonationBridge.v1`. Он не открывает интернет-соединения,
не запускает внешние процессы и не исполняет Lua-код из сообщений.

Версия аддона **0.6.3** работает с программой
**1.6.3 Beta** и протоколом v2.
Обновите EXE и аддон при закрытых программе и игре. Загрузка сохранения сохраняет
pipe, ID Lua-сессии и последние 256 ответов. `RESULT_QUERY` только возвращает
сохранённый ответ: неизвестная команда или другая сессия дают `uncertain`,
но никогда не вызывают эффект. Новая игра не требуется; после установки нужен
полный перезапуск движка.

Транспорт: `spawn_vehicle` создаёт одну из 30 машин F1-спавнера Chronicles IX-Ray,
включая 7 legacy, на ближайшей свободной площадке: сначала в пределах 10 м,
затем расширенным поиском до 100 м. Проверяемая площадка
учитывает габариты выбранной модели. Параметр `fuel_level`: целое 1–10 литров,
где 5 — ровно 5 л независимо от объёма бака. Имя ключа сохранено для совместимости
настроек, старое число теперь означает литры. ACK приходит после
появления online-объекта и фактической установки `CCar.fuel`. Через 5 секунд
неудачного ожидания удаляется только созданная этой командой машина; если
откат не подтверждён, результат `uncertain`. При загрузке сохранения ожидающий
setter отменяется, команда не повторяется. Новой игры не требуется.

Legacy-машины используют те же поля `CCar.fuel/fuel_tank`, но не обязаны иметь
opt-in DCP fuel profile. Их расход, HUD и заправка остаются штатными. Скрипт
не включает им новый профиль и не меняет настройки/физику самих автомобилей.

В test.2 исправлена ложная ошибка `vehicle_ray_api_unavailable`: `ray_pick`
проверяется созданием экземпляра, а не типом «функция», поскольку IX-Ray
экспортирует вызываемый luabind-класс. Реальное отсутствие API отклоняет
команду до спавна; только временно занятое место остаётся в ожидании.

`explode_nearest_vehicle` вызывает штатный `CCar.CarExplode()` только для
ближайшей живой несюжетной машины в выбранном радиусе 1–2000 м (по умолчанию 5).
Взрыв опасен для игрока, окружающих NPC и содержимого багажника. Оба пресета
не активируются автоматически и исключены из «Рандом по ВСЕМ».
Канистра уже присутствует в безопасном списке предметов; EXE показывает её
отдельно в категории **Топливо**.

Поддерживаемые действия перечислены в `configs\pf_donation_actions.ltx`.
Три стартовых действия включаются программой по умолчанию:
`add_radiation`, `drop_active_weapon`, `spawn_mutants` (три собаки по
предустановленным параметрам). Универсальные `spawn_npcs`, `change_health`,
`god_mode`, `change_needs`, `spawn_items`, `change_money`, `spawn_anomaly`, `get_drunk`,
`trigger_emission`, `sleep_hours`, `drop_outfit`, `damage_equipment`, `drop_random_items`,
`teleport_random`, `spawn_random_hostile_squad`, `spawn_random_mutant_pack` и
мета-пресеты `random_active`, `random_all_presets` поставляются как шаблоны,
пока пользователь сам не создаст для них активные варианты и ценовые правила.

Старый идентификатор `spawn_dogs_3` остаётся зарегистрирован только для
совместимости с ранее экспортированными правилами и намеренно скрыт из
манифеста. `spawn_anomaly` использует только подтверждённые игровые секции,
принимает дальность 0–100 метров (`0` создаёт зону непосредственно в позиции
актёра), ограничивает время жизни диапазоном 10–300 секунд и удаляет созданный
объект при истечении таймера или загрузке сохранения.

`spawn_mutants` поддерживает все виды из подтверждённого встроенного игрового
спавнера: `dog`, `boar`, `flesh`, `tushkano`, `pseudodog`, `psy_dog`,
`bloodsucker`, `snork`, `burer`, `controller`, `poltergeist`, `chimera` и
`pseudogiant`. Если у вида нет трёх самостоятельных секций силы, несколько
положений общего переключателя намеренно указывают на одну существующую
безопасную секцию.

`spawn_mutants` и `spawn_npcs` принимают одну или несколько строк в одной
команде. Для каждой строки задаются вид/группировка, сила и количество `1..99`.
Все строки проверяются до первого создания и откатываются целиком при
подтверждённой частичной ошибке. Старые команды с одиночными
`species/faction`, `strength` и `count` остаются совместимыми.

`spawn_items` принимает один или несколько предметов в рамках одной команды.
Каждая строка отдельно задаёт section ID и количество `1..50`; весь список
проверяется до первого создания и откатывается целиком при подтверждённой
частичной ошибке. Старые команды с единственным `item/count` остаются
совместимыми. Каждый предмет должен быть одновременно зарегистрирован в
`inventory_sort_registry` и в открытом
`configs/mod_system_pf_donation_item_allowlist.ltx`. Windows-программа строит
из них двухуровневый список **категория → предмет**. Lua повторно сверяет оба
реестра, группу, `quest_item`, `can_trade`, `can_take`, `story_id`, транспорт и
служебный класс мировых взрывных объектов. Поэтому список F1 используется как
источник категорий, но не считается разрешением сам по себе.

Специальный выбор **Случайное оружие** не является секцией и намеренно не
добавлен в allowlist. При выполнении Lua заново строит пересечение группы
`weapons` с donation allowlist, исключает квестовые и защищённые секции,
выбирает один допустимый тип и создаёт указанное число экземпляров именно этого
типа. Транспорт, сервисные объекты и другие категории в выбор не попадают.

Русские названия безопасного каталога находятся в
`configs/pf_donation_item_labels_ru.ltx`. Это только UI-sidecar: ключом служит
настоящий section ID, а значение используется исключительно как подпись в
Windows-программе. По pipe и в Lua всегда передаётся исходный section ID;
sidecar не расширяет allowlist, не регистрирует действия и не исполняется
игрой. Если подписи нет, программа показывает технический section ID и
предупреждает о неполном словаре.

Дополнительные действия не исполняют произвольный текст доната:

- `god_mode` включает штатную консольную команду `g_god 1` на `5..600` секунд и затем
  возвращает состояние, сохранённое перед первым срабатыванием. Повторная
  команда продлевает эффект; загрузка сохранения немедленно запускает
  восстановление, чтобы временная неуязвимость не стала постоянной. Если IX-Ray
  пересоздал общий registry при загрузке, runtime восстанавливает обработчик
  перед выполнением команды;
- `get_drunk` напрямую включает штатный эффект опьянения на выбранное число
  секунд, не создавая и не расходуя предметы;
- `change_needs` одним пресетом независимо настраивает голод и жажду:
  положительный процент утоляет потребность, отрицательный усиливает её, ноль
  не меняет соответствующую шкалу;
- `trigger_emission` вызывает только штатный менеджер выброса; если выброс уже
  идёт, локация или текущий сюжетный этап его запрещают либо нет укрытий,
  событие отклоняется и не превращается во второй выброс из очереди;
- `sleep_hours` без окна выбора запускает штатное затемнение и плавное
  пробуждение на `1..24` часа: в середине эффекта сдвигает время, расходует
  голод и жажду, обновляет погоду и восстанавливает выносливость; при
  небезопасном состоянии действие откладывается;
- `drop_outfit` оставляет выбранную обычную броню и/или шлем на земле, но не
  трогает квестовые и защищённые вещи. В режиме «оба» обрабатывается каждый
  фактически надетый подходящий предмет, даже если второй слот пуст;
- `damage_equipment` уменьшает текущее состояние выбранной брони, шлема или
  обоих предметов на `1..100` процентных пунктов. Сюжетные, квестовые и
  неторгуемые вещи защищены; при выборе обоих предметов Lua использует каждый
  фактически надетый подходящий предмет и тот же проверенный снимок экипировки при
  выполнении, а частичная ошибка движка возвращает `uncertain`;
- `drop_random_items` сначала собирает безопасные физические предметы из всего
  рюкзака, затем выбрасывает заданное число из любых типов и стаков; один объект
  не выбирается дважды, а патроны считаются целыми коробками. Если подходящих
  объектов меньше заданного количества, действие выбрасывает все доступные;
- `teleport_random` сначала равномерно выбирает одну случайную дальность во
  всём заданном диапазоне, затем среди проверенных направлений выбирает
  безопасную навигационную вершину текущей локации, ближайшую к этой дальности;
  старый направленный поиск остаётся резервным;
- `spawn_random_hostile_squad` создаёт независимых NPC без simulation squad
  только из группировки, которая сейчас враждебна персонажу; `minimum_count` и
  `maximum_count` задают включительный диапазон `1..99`; большие группы могут
  сильно нагрузить игру и требуют достаточного числа безопасных вершин;
- `spawn_random_mutant_pack` выбирает один из подтверждённых безопасных видов
  и создаёт отдельных мутантов этого вида без simulation squad, также в
  заданном включительном диапазоне `1..99`;
- `random_active` и `random_all_presets` разрешаются только Windows-программой
  в конкретное обычное действие. Для `random_all_presets` программа дополнительно
  применяет сохранённый список разрешённых пользователем пресетов; предметные,
  составные и мета-действия в него не включаются. Lua-регистрации обоих мета-ID
  остаются закрытыми предохранителями и отклоняют ошибочно дошедшую мета-команду.

## Добавление действия

1. Создайте отдельный файл `scripts\pf_donation_action_<id>.script`.
2. В конце файла вызовите:

```lua
pf_donation_registry.register("my_action", {
	source = "scripts\\pf_donation_action_my_action.script",
	can_execute = function(context, params)
		return true
	end,
	execute = function(context, params)
		return "executed", "my_action_done"
	end
})
```

`can_execute` не должен менять мир. Для временно небезопасного состояния он
возвращает `false, "deferred", "reason"`, для неправильных параметров —
`false, "rejected", "reason"`. Ошибка после начала изменения мира считается
`uncertain`, поэтому многосоставное действие обязано откатывать частичный
результат самостоятельно.

3. Добавьте секцию `[action:<id>]` в `configs\pf_donation_actions.ltx` с полями
`name`, `description`, `script`, `default_active`, `cooldown_seconds`,
`default_params` и схемой параметров `param.<key>`.
4. Добавьте имя модуля в `addon.init` и
`configs\mod_script_pf_donation_alerts.ltx` перед `pf_donation_runtime`.
5. Полностью перезапустите игру. Загрузка сохранения не перезагружает все Lua-модули.

Идентификатор действия ограничен шаблоном `^[a-z0-9_.-]+$`. Параметры
принимаются только после явной проверки действием; неизвестные параметры
должны отклоняться. Команда никогда не должна использовать `loadstring`,
`dofile` или иное динамическое исполнение текста.
